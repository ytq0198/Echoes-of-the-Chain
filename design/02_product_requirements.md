# ChainGrade 产品需求规格 v0.1

状态：已冻结首版范围  
日期：2026-08-25

## 1. 产品定位

ChainGrade 是面向高校成绩签发、学生持有和第三方核验的隐私保护型可信学业凭证平台。它不替代教务系统，而是连接教务系统、学生和外部验证方，为成绩记录提供可追溯签发、最小披露和无需回访学校的真实性核验。

## 2. 要解决的问题

1. 电子成绩单容易被修改，纸质或截图核验依赖人工回访学校。
2. 学生通常只能分享整份成绩单，无法只披露申请所需的课程或能力。
3. 成绩更正、撤销和申诉过程分散，外部验证方难以确认当前有效版本。
4. 单一数据库管理员可以覆盖历史记录，跨院系或跨学校缺少共同信任。
5. 传统验证链接往往永久有效，学生无法控制用途、次数和过期时间。

## 3. 角色与权限

| 角色            | 身份来源                              | 核心权限                                       |
| --------------- | ------------------------------------- | ---------------------------------------------- |
| 教师/成绩录入员 | 学校组织 MSP，`app.role=issuer`       | 新建成绩草稿、查看本人提交记录、发起修订       |
| 院系复核员      | 学校组织 MSP，`app.role=reviewer`     | 复核签发、拒绝草稿、撤销凭证、处理申诉         |
| 学生            | 学校组织 MSP，`app.role=student`      | 查看本人凭证、发起申诉、创建/撤销披露授权      |
| 外部验证者      | 无登录或验证组织身份                  | 凭一次性能力链接核验已授权声明和当前状态       |
| 联盟管理员      | 各组织 MSP，`app.role=admin`          | 管理机构、课程模式和可信签发者，不可直接改成绩 |
| 审计员          | 监管/验证组织 MSP，`app.role=auditor` | 查看最小化审计事件与统计，不读取成绩明文       |

## 4. 核心用户故事与验收

### Epic A：成绩凭证签发

- 教师可手工录入或通过 CSV 导入成绩草稿。
- 草稿包含课程、学期、成绩组成、最终成绩和学生标识，但公共账本只保存不可逆标识、承诺和状态。
- 复核员与提交人必须是不同身份；复核通过后凭证变为 `ACTIVE`。
- 每次状态改变均产生可查询的 Fabric 交易 ID 和确定性时间戳。

### Epic B：查询与验证

- 学生只能看到自己的成绩详情。
- 验证者无需注册即可使用限时链接或二维码。
- 验证页明确展示：签发机构是否可信、密码学证明是否通过、凭证是否有效、授权是否过期/耗尽。
- 验证失败必须给出可理解但不泄漏敏感信息的原因。

### Epic C：修订与撤销

- 任何更正均创建新版本，不覆盖旧记录。
- 新版本复核通过时，旧版本原子地标记为 `SUPERSEDED`。
- 撤销必须记录原因承诺和操作者身份；撤销后所有分享链接验证失败。

### Epic D：轻量申诉

- 学生可针对自己的有效凭证提交一次结构化申诉和证据摘要。
- 申诉正文和证据不进入公共账本；公共账本仅记录哈希、状态和关联凭证。
- 复核员可接受或驳回，并记录决定摘要哈希。
- 接受申诉不会直接篡改成绩，而是进入正常修订与复核流程。

### Epic E：隐私披露

- 学生选择披露字段、用途、验证者、过期时间和最大使用次数。
- 分享令牌只保存哈希，明文令牌只在创建时返回一次。
- 第一阶段支持按字段披露；后续在同一项目中增加不可链接派生证明和阈值谓词。
- 审计日志不得保存披露的成绩值或完整令牌。

## 5. 非功能要求

- 安全：最小权限、输入验证、防重放、密钥不入库、敏感日志脱敏。
- 隐私：默认拒绝；公共账本不得含姓名、学号、成绩、申诉正文或证据文件。
- 可用性：四类角色均有独立、清晰的操作路径，关键任务不超过 5 个主要步骤。
- 可测试：核心链码分支单元测试覆盖率目标不低于 85%，关键 E2E 流程全覆盖。
- 性能：给出 Caliper 基准；报告吞吐、平均/P95 延迟和失败率，不预设虚假指标。
- 可部署：全栈 Docker Compose 一键启动；提供健康检查、初始化和清理脚本。
- 可审计：所有链上变更可关联交易、身份、组织和上一版本。

## 6. MVP 与后续范围

### M1：链码技术尖峰

实现草稿、复核签发、修订、撤销、查询、申诉和角色检查，使用模拟上下文完成单元测试。

### M2：课程可运行版

接入真实 Fabric 多组织网络、API、PostgreSQL 和 Web 工作台，完成主要 E2E 流程。

### M3：完整产品与课程答辩里程碑

加入 CSV、二维码、限时授权、看板、错误体验、测试报告、PPT 和视频脚本。

### M4：同一项目的竞赛深化里程碑

在 M3 的同一代码库、产品和部署架构上加入标准 VC、BBS+/匿名凭证技术尖峰、阈值证明、跨机构验证和 Caliper/攻击实验；不另建项目或产品分支。

## 7. 明确不做

- 不发行 Token、NFT 或任何可交易资产。
- 不保存或演示真实学生成绩与学号。
- 不声称链上数据天然真实；真实性来自可信签发流程和背书治理。
- 不自研密码学算法，只集成公开规范及经过审查的实现。
- 首版不开发原生移动 App，以响应式 Web 钱包和二维码替代。
