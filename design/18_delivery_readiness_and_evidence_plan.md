# 统一交付、演示与证据设计

## 1. 阶段目标

Iteration 12 不增加脱离成绩管理的新模块，而是把已经完成的 ChainGrade 变成可稳定答辩、可严格匿名参赛、可由证据复核的同一个项目。课程和竞赛只在材料时长、身份信息与评审重点上有不同编排，不复制代码、账本、界面或产品名称。

## 2. 要求覆盖与缺口

| 评审维度 | 已有覆盖 | 本阶段补齐 | 后续工作 |
| --- | --- | --- | --- |
| 课程美观性 20% | 完整视觉系统、桌面/移动验收 | 答辩截图复验与证据索引 | 按现场设备微调 |
| 课程实用性 30% | 批量签发、查询、修订/申诉、验真 | 7 分钟场景化故事线 | 真实教务接口需授权后接入 |
| 课程完整性 30% | 四角色闭环、真实 Fabric、测试与恢复 | 一键预检/启停、课程材料骨架 | PPT、视频最终导出 |
| 课程创新性 20% | 私有数据、承诺、版本审计、有限披露 | 统一创新叙事与边界声明 | BBS+ 技术尖峰 |
| 竞赛可行/完整 | 同一 B/S 产品和可执行代码 | 匿名设计/测试报告骨架 | 性能基准与最终打包 |
| 竞赛创新/前景 | 隐私边界、原子批量、可信异议处理 | 可量化证据映射 | 跨机构互认、匿名凭证 |

## 3. 单项目、双编排

共同事实层位于 `deliverables/common`，只记录已经实现且可复验的能力。课程编排可包含团队分工，按 7 分钟陈述/演示组织；竞赛函评编排严格匿名，按设计报告、测试报告和其他文件组织。两者必须引用同一证据索引，不允许出现一边宣称已完成、另一边仍标记规划的冲突。

## 4. 可重复演示控制

`infra/demo/preview.sh` 只管理 API 和 Web，不隐式重置账本。启动前验证原生网络、链码、端口和工具，私有认证变量只从权限为 600/400 的 Git 外文件加载。停止时验证 PID 的命令行属于当前项目，避免结束同机其他进程。Docker 故障继续采用已验证的原生 Fabric 路径，不临场修复共享 Docker。

## 5. 证据分级

- A 级：真实 Fabric 双 Peer/交易/私有读取或恢复证据。
- B 级：自动测试、真实 HTTP 与浏览器 UI 证据。
- C 级：设计说明或尚未实测的计划。

“真实链上”“隐私隔离”“原子回滚”等结论至少需要 A+B；界面完成度至少需要桌面/移动截图和 console/overflow 检查；未来能力只能标记 C 级。

## 6. 匿名安全门

竞赛工作区不得出现学校、成员、指导人员、个人邮箱或个人仓库身份。自动扫描作为提交前最低门槛，但 PDF 作者属性、图片 EXIF、视频属性、源码 Git 历史和压缩包清单必须人工复核。课程成员分工文件不得复制进竞赛包。

## 7. 本阶段退出标准

1. 服务器真实 Fabric 下预检、启动、状态、停止可重复执行，秘密不进入日志或 Git。
2. 7 分钟脚本完成一次计时彩排，并记录主线与回退耗时。
3. 课程/竞赛材料骨架引用同一证据索引，竞赛文本匿名扫描通过。
4. 全量检查、测试、构建通过；核心 UI 桌面/移动复验且截图嵌入阶段报告。
5. 本机、服务器和 GitHub 指向同一提交；Docker 真实故障状态如实记录。
