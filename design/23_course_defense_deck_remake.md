# ChainGrade 课程答辩 PPT 重制设计

日期：2026-08-29

## 1. 重制目标

原 9 页答辩稿已经能覆盖课程要求，但叙事更接近“功能清单”，系统为何必须使用区块链、隐私与修订为何不能分开处理、证据如何支持结论，还可以讲得更直接。本次重制不改变项目范围，也不建立竞赛版分叉；课程答辩与后续竞赛继续使用同一个 ChainGrade 项目。

重制后的核心命题为：

> 成绩可信，不等于把成绩写上链；可信来自身份、复核、隐私、修订与申诉组成的可验证流程。

## 2. 为什么扩展为 13 页

课程主讲仍控制在 420 秒。13 页不是增加专业名词，而是把原来挤在一页中的设计原因、机制和证据拆开，让每页只回答一个判断问题：

1. 为什么简单上链不够；
2. 总设计怎样同时解决公开验证、隐私和纠错；
3. 一条交易怎样穿过身份与 Fabric 边界；
4. 角色、状态机、申诉和授权披露如何形成闭环；
5. 真实界面、真实交易、测试与恢复数据能否复核。

演讲备注分别分配约 20–40 秒，总时长保持 420 秒。

## 3. 视觉系统

- 画布：16:9，1280×720；
- 背景：纸张灰 `#F5F5F3`；
- 主色：可信蓝 `#07448C`；
- 辅色：技术蓝 `#2E6A9E`；
- 强调：批注金 `#F0C86A`；
- 标题：Georgia / 宋体，42 px；
- 正文：Segoe UI / 微软雅黑，24 px；
- 结构：编辑式大标题、细分隔线、不等宽证据区和克制留白，不采用整页同款卡片网格。

封面和结尾各使用一次大型“可信 / 可验证”艺术字，正文页的大标题仍遵守统一字号。页面不出现工具提示词、小组内部说明或 AI 生成痕迹。

## 4. 图示设计

### 系统架构

架构图按“角色端—应用边界—Fabric 网络”三类信任区组织，主交易左到右，transient 私有路径单独用虚线表示。图中只保留工作台、Web、API/Gateway、Chaincode 和双 Peer 等必要节点，避免把部署清单画成拓扑墙。

### 凭证生命周期

状态机突出 `SUBMITTED → ACTIVE → SUPERSEDED` 主路径，并保留 `REJECTED`、`APPEALED`、`REVOKED` 分支。设计重点不是状态数量，而是展示“修订创建新版本、旧记录继续可验证”。

### 隐私边界

隐私图只区分三种可见性：公开账本、隐式私有集合和授权主体。公众、本人与外部验证者分别能看到什么，直接写在图中；授权路径同时列出字段、用途、验证者、期限和次数。

## 5. 真实产品证据

P07、P09、P10 仅使用项目既有浏览器验收截图，全部保持原始比例，不裁切：

- 学生端申诉进度；
- issuer 签发工作台；
- reviewer 独立复核工作台；
- student 本人私有详情；
- public verifier 公开验真。

截图承担“产品确实存在”的证据作用；流程、标签和结论仍用原生可编辑文字，不把说明烘焙进图片。

## 6. 数据口径

答辩稿只使用最终实验报告已有数据：

- 25 个链码方法；
- 25 个 HTTP 路由；
- 52/52 自动测试；
- 语句、分支、函数、行覆盖率为 85.91%、75.38%、95.52%、85.98%；
- 双 Peer 账本高度 12/12，当前与前序区块哈希一致；
- API/Web 冷构建并启动 12.50 秒；
- ACTIVE 交易 ID 显示为 `c7f5827e … becf7a7`。

P12 覆盖率条按统一 360 px 轨道计算，四条长度分别为 309、271、344、310 px。所有数字均保留明确来源，同时在页面上写出“分支覆盖仍需补测”的局限。
