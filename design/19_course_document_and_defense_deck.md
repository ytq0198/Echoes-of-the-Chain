# 课程项目介绍与答辩材料设计

## 1. 阶段目标

本阶段不增加新业务模块，而是把同一个 ChainGrade 项目的实现、真实链上数据、界面证据和工程边界压缩成两件可提交材料：项目介绍文档与 7 分钟课程答辩 PPT。两件材料与最终实验报告引用同一事实层，不另造“课程版”产品。

## 2. 沟通目标

答辩结束时，课程教师应能理解：ChainGrade 的价值不是把更多成绩字段公开上链，而是用 Fabric 身份和状态机约束变更，用私有数据集合保护明文，用公共承诺支持验真，并且这些设计已经由交易、双 Peer、自动测试和恢复实验验证。

项目介绍文档承担完整解释任务，按“问题—架构—数据边界—状态机—功能—安全—界面—实验—恢复—边界”展开。PPT 承担口头陈述任务，保留 9 个推进故事的页面，不把报告段落直接缩小粘贴到幻灯片。

## 3. 项目介绍文档结构

文档采用白底、深绿主色和金色章节标记，正文以原因、实现形式和实测结果为主。核心取舍如下：

- 首页直接给出项目定义、成员、技术栈和仓库，不增加宣传口号或制作提示词。
- 公共账本与私有侧数据用对照表解释，明确为什么某字段公开或不公开。
- 凭证、申诉状态机用合法转移说明“可纠错但不覆盖历史”。
- 实验部分摆出 52/52、12/12、交易结果、覆盖率、备份大小与恢复时间，不以“高性能”“高安全”等空泛形容词代替数据。
- 局限单列单 orderer、受控身份、bearer capability、合成数据与未完成基准，避免把下一阶段计划写成当前成果。

## 4. 7 分钟答辩叙事

| 页 | 叙事任务 | 建议时长 |
| --- | --- | ---: |
| 1 | 一句话定义同一项目 | 30 秒 |
| 2 | 解释隐私、纠错、复核冲突 | 45 秒 |
| 3 | 说明四层架构与数据分界 | 55 秒 |
| 4 | 说明版本状态机与轻量申诉 | 55 秒 |
| 5 | 用真实 UI 证明四角色产品化 | 45 秒 |
| 6 | 说明证书属性和失败路径 | 45 秒 |
| 7 | 展示测试、Peer 与恢复数据 | 55 秒 |
| 8 | 解释 Docker 故障下的恢复证据 | 50 秒 |
| 9 | 回扣结论与同项目后续 | 40 秒 |
| 合计 |  | **420 秒** |

每页只承担一个结论，标题使用可直接口述的判断句。演讲备注包含讲解提示和 `[Sources]` 来源块，便于复核数字和截图出处。

## 5. 视觉系统

答辩材料借鉴 Codex Grid 的大字号、细分隔线、白底和低密度页面结构，同时把项目 UI 的深绿和金色作为唯一强调色。封面和结论采用大标题；架构与生命周期使用原生可编辑图形；产品页只使用一张真实 Fabric 总工作台截图；数据页仅保留三项最能支撑完成度的指标。

所有幻灯片保持 1280×720、标题不换行、正文不低于可读字号。避免按钮、导航、徽章和密集卡片造成“后台页面截图化”；只有量化证据页使用三块等宽数据区域。

## 6. 验收标准

1. DOCX 可解包，14 页逐页渲染无空白题注页、空列表、跨页孤行表头或页脚覆盖。
2. PPTX 可解包，9 页逐页渲染无截断、重叠、异常换行和画布溢出。
3. 9 页演讲备注均包含成对 `[Sources]` 标记。
4. 所有实测数字与 `reports/`、`design/` 和源码证据一致。
5. 材料不出现制作提示词、演示账号、密码、私有成绩明文或竞赛匿名材料不应包含的身份信息。
