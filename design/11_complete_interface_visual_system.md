# Iteration 5 完整界面视觉系统与二维码验真设计

日期：2026-08-26

## 设计目标

将 Iteration 4 已验证的可信成绩工作台视觉语言扩展到全部业务界面，避免首页精致而角色工作台仍停留在普通后台表单。课程答辩与竞赛提交继续使用同一个产品和同一套界面。

## 视觉语言

- 业务正文使用清晰的无衬线系统字体；大型中文标题使用项目内自托管的 Noto Serif SC Variable，形成带有档案、证书和学术气质的展示字形。
- 页面标题采用章节编号、中文主标题、英文流程标记和一句产品化说明组成的锁定排版。
- 色彩继续以墨绿表达可信与授权，以纸张米白表达凭证和档案，以金色章节编号建立识别度。
- 教师、复核员、学生与公开验证者均使用同一流程导航、左侧角色说明、右侧业务内容和最小披露原则栏。
- 按钮、表单、哈希字段、状态标签、结果卡和空状态使用统一圆角、间距、边框和焦点反馈。
- 图标统一来自 Phosphor Vue；二维码由 qrcode.vue 根据真实验真 URL 生成，不使用占位图或手绘图形。

## 页面结构

1. 教师签发：成绩草稿和不可覆盖修订放入同一内容列，左侧说明 transient data 与隐式私有集合边界。
2. 独立复核：公开承诺查询、凭证详情和申诉结论按任务顺序纵向排列，避免长哈希被挤入窄栏。
3. 学生凭证：凭证卡、本人私有披露、二维码分享和轻量申诉形成完整持有者旅程。
4. 公开验真：支持正确哈希、错误哈希和二维码 URL 预填三种关键状态。
5. 登录与权限：未登录和角色不匹配使用同一身份验证界面，并明确当前会话与目标角色。

## 二维码验真边界

二维码 URL 只包含 `credentialId` 和公开的 `detailHash`。二维码不包含成绩、等级、盐值、申诉正文、学生姓名或学生匿名主体哈希。公开页面根据 URL 参数恢复验真字段，仍需由核验者主动发起链上查询。

## 响应式策略

- 桌面端使用 310 px 角色说明列和自适应内容列。
- 移动端转为单列，章节编号和艺术标题按比例缩小。
- 四阶段导航在 390 px 视口中等分显示，不产生横向滚动条。
- 二维码分享卡在移动端转为纵向，操作按钮改为满宽堆叠。

## 验收要求

- 浏览器连接服务器真实 Fabric 账本，验证公开凭证、已处理申诉、本人私有成绩、正确验真与错误哈希状态。
- 覆盖 1440×1000 桌面视口和 390×844 移动视口。
- 检查页面横向溢出、控制台 warning/error、移动菜单、登录门与角色不匹配状态。
- 截图存放于 `reports/assets/iteration-5/final/` 并嵌入阶段实验报告。
