负责人：待两名组员自主选择后确认。

建立任何评审者都能复跑的 ChainGrade 性能与可靠性实验，而不是给出一次手工计时或估算 TPS。实验必须隔离于现有确定性演示账本，保留环境、负载、原始数据、统计方法和异常说明。

## 3. 基准隔离

服务器专用目录为 `/mnt/localDisk3/weizian/ChainGrade-benchmark`。不得在现有 `/mnt/localDisk3/weizian/Echoes-of-the-Chain` 演示账本上持续压测，也不得修改共享 Docker data-root。

专用环境必须具备：

- 明确且不冲突的 orderer、Peer、CCAAS、API 端口；
- 独立 PID、日志、账本、私钥和数据目录；
- 受限 reset，只能删除专用运行目录且需要显式确认；
- 每次运行前保存 commit、CPU、内存、Node/Fabric 版本、链码 sequence 和初始高度；
- 每次运行后保存最终高度、current/previous hash 和异常交易数量。

如果无法做到隔离，应暂停并请组长裁决，不得为了赶进度污染演示证据。

## 4. 必测负载

| 负载 | 类型 | 主要指标 | 数据要求 |
| --- | --- | --- | --- |
| 公共验真 | 只读 | 吞吐、P50/P95/P99、HTTP 错误 | 固定有效凭证集合，随机均匀读取 |
| 学生私有查询 | 鉴权只读 | 会话开销、P95、403/401 误差 | 不记录成绩明文和 Cookie |
| 签发 + 独立复核 | 写入链路 | API 延迟、提交/确认延迟、成功率 | 每次使用唯一 ID，issuer/reviewer 分离 |
| 原子批量 | 写入链路 | 每交易条目数、确认延迟、冲突回滚 | 至少 1、10、25、50 条批次 |

并发档为 1、5、10、20。每档先预热，再执行三次正式运行；每次运行顺序需随机或轮换，避免服务器热状态固定偏向某一档。正式时长和请求数由技术尖峰确定，但同一矩阵内必须一致。

不预设 TPS 达标线。验收关注方法可重复、数据完整、没有无效已提交交易，并如实解释瓶颈和波动。

## 5. 故障实验

仅在专用基准网络依次执行：

1. 停止 Org2 Peer：记录受影响请求、错误类型、恢复时间和恢复后高度/哈希；
2. 停止 CCAAS：记录读写差异、链码恢复时间和积压行为；
3. 停止单 orderer：验证写入按预期失败并在恢复后恢复，明确当前不是高可用拓扑；
4. 每种故障完成后运行一致性查询，不能只凭进程 RUNNING 判定恢复成功。

本阶段不要求把单 orderer 改成三 orderer；三 orderer 只作为必做项完成后的伸展实验。

## 6. 输出格式

建议目录：

```text
infra/benchmark/
  README.md
  preflight.sh
  run-matrix.mjs
  workloads/
  aggregate.mjs
  schemas/
reports/assets/iteration-14-benchmark/
  environment.json
  raw/
  summary.csv
  charts/
```

图表必须由原始数据自动生成；报告同时给中位数和三次运行范围，不能只挑最好一次。原始文件如含路径、用户名、主机名或凭据，先生成匿名摘要，原始敏感数据不进入竞赛提交包。

## 7. Definition of Done

- 专用基准网络可预检、启动、停止和复跑，不触碰共享 Docker；
- 四类负载和并发矩阵全部生成原始数据，至少三次重复；
- 聚合程序自动输出吞吐、P50/P95/P99、失败率和资源数据；
- 写负载前后区块高度变化可解释，没有未知无效交易；
- 三类故障均记录失败窗口、恢复时间和恢复后双 Peer 一致性；
- 报告不填写估算性能，不隐瞒失败或异常值；
- 代码、脚本、数据摘要和报告由最终选择本工作包的成员本人提交，提交信息可追溯。

## 8. 伸展项

必做项完成后，可尝试三 orderer Raft 专用拓扑，对比单 orderer 与三 orderer 的写入可用性和恢复行为。伸展项必须使用独立端口与目录，不能修改现有演示网络。
