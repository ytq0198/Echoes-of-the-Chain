# 课程大作业最终收口设计

## 1. 收口目标

课程答辩和后续竞赛使用同一个 ChainGrade 项目。本阶段不新增业务范围，只把已经合并的基础系统、标准 VC 互操作和可靠性基准统一进代码事实、实验报告、项目介绍、答辩稿与提交清单，消除旧版本数字不一致的问题。

## 2. 事实基线

最终材料只采用以下可复核结果：

| 项目 | 最终事实 |
| --- | --- |
| Fabric 网络 | Org1、Org2 双 Peer，Raft 单 orderer，链码 `grade 0.9 / sequence 1` |
| 接口规模 | 25 个链码公开方法，28 条 HTTP 路由 |
| 工程规模 | 83 个源码/测试/运维文件，12,637 行 |
| 项目测试 | shared 33、chaincode 20、API 67，共 120 项通过 |
| 基准工具测试 | 7 项通过 |
| 正式负载 | 7 类负载 × 4 档并发 × 3 次重复，共 84 个单元，合法请求失败 0 |
| C20 公开验真 | 中位吞吐 746.614 req/s，P95 38.202 ms |
| 稳态恢复 | Org2 Peer 14.030 s，CCaaS 16.870 s，orderer 22.482 s |
| 成员贡献 | 魏子安 4、强璞 3、阳震 3，合计 10 分 |

## 3. 材料单一来源

最终报告、项目介绍与答辩 PPT 必须引用同一事实基线。历史文档可以保留当时的阶段数据，但 `deliverables/course/` 的最终入口不得继续出现 52 项测试、25 条 HTTP 路由或“VC/性能基准尚未完成”等旧结论。

## 4. 验收门槛

1. `pnpm check`、`pnpm test`、`pnpm build` 与基准工具 7 项测试全部通过。
2. PDF 按 A4 导出后逐页检查；DOCX 用 Word 导出后逐页检查；PPTX 从最终文件重新渲染后逐页检查。
3. Git 差异无尾随空格或冲突标记，最终提交入口与贡献表清晰。
4. 本机、GitHub 主分支和学校服务器工作副本指向同一提交。

## 5. 人工动作边界

演示视频必须由小组成员使用真实系统操作并配音，不能用文档或伪造素材替代。本阶段提供逐镜头脚本、启停命令和故障回退方案；最终录制、观看复核以及填写课程组号属于提交前人工动作。
