# 强璞工作包：标准凭证互操作与验证体验

## 1. 目标

在现有 Fabric 成绩凭证之上增加可导出、可传递、可独立验证的标准化凭证层。该层不替换公共账本和私有数据集合，而是把当前 ACTIVE 凭证映射成可下载 JSON，并把签名、链上状态和详情承诺一起纳入验证。

默认二维码只包含验证地址、凭证 ID 和摘要，不包含课程名、分数、等级、盐值或完整凭证文件。

## 3. 最小数据约束

必做版本使用 VC 2.0 风格的数据结构，但只有通过实际测试的部分才能表述为支持：

- `type` 至少包含学业成绩凭证类型；
- `issuer` 指向可公开识别的演示签发者标识，不写学校或成员身份到匿名材料；
- `credentialSubject` 只包含学生主动导出的字段；学生标识使用项目 subject hash；
- `credentialStatus` 可查询 ACTIVE、SUPERSEDED、REVOKED 等链上状态；
- `evidence` 或等价扩展保存 channel、credentialId、detailHash、签发组织和交易/区块引用；
- `proof` 使用 Ed25519，并明确签名算法、创建时间、验证方法和 proof purpose；
- 规范化字节和签名字节必须由测试固定，不能依赖普通 `JSON.stringify` 的偶然属性顺序。

不得把普通 JSON 签名表述为 BBS+、零知识证明或不可链接选择性披露。BBS+ 只允许放在完成必做项后的独立尖峰目录。

## 4. 安全与负向测试

至少覆盖：

1. 修改课程、分数或 Fabric 锚定后签名失败；
2. 使用未知验证方法或错误公钥失败；
3. 凭证签名正确但链上状态为 REVOKED 或 SUPERSEDED，结论不得显示“当前有效”；
4. `detailHash` 与公共账本不一致；
5. 上传超限、非 JSON、重复键或缺失必填字段；
6. 导出和验证响应使用 `Cache-Control: no-store`，日志不记录凭证正文；
7. 二维码默认不出现分数、课程名和完整 token。

## 5. UI 验收

必须通过 1536×1024、1440×900、1280×720、390×844。每个视口检查：

- 学生导出前字段预览和隐私说明可见；
- 未选择字段时不能生成空凭证；
- 公开验证结果分别展示“签名、链上状态、详情锚定”，不只给一个绿色成功标签；
- 文件解析、网络失败、已撤销、已取代和篡改状态有不同说明；
- `scrollWidth === clientWidth`，console warning/error 为 0。

截图保存到 `reports/assets/iteration-14-vc/`，并嵌入本人阶段报告。

## 6. Definition of Done

- 新功能无需演示账号硬编码和私钥入库；
- 原有测试全部通过，并新增不少于 18 个有效测试；
- 一个真实 ACTIVE 凭证可导出、下载、重新导入并通过签名/状态/锚定校验；
- 同一文件任意受保护字段被修改后验证失败；
- 撤销或取代后重新验证给出正确非有效结论；
- 四视口浏览器验收与报告齐全；
- 代码、设计、测试和截图由强璞本人提交，提交信息可追溯。

## 7. 伸展项

必做项全部完成后，可在隔离目录完成 BBS+ 库兼容性尖峰，只需回答密钥格式、证明大小、生成/验证时间和浏览器支持四个问题。尖峰不能改变主流程，也不能在未完成时进入竞赛“已实现功能”列表。
