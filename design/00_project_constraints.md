# 项目约束与验收清单

更新日期：2026-08-25

## 1. 课程硬约束

依据实验目录中的课程要求与参考选题：

1. 三人小组完成具有实用场景的原创 B/S 应用。
2. 区块链层必须采用 Hyperledger Fabric。
3. 前端、后端、智能合约和 SDK 调用均需完整，且可在本机浏览器正常预览。
4. 页面应美观、功能应完整，并体现实际价值。
5. 课程提交物包括源代码、答辩 PPT、项目介绍文档、演示讲解视频、成员分工及贡献评分。
6. 课程评分：美观性 20、实用度 30、完整性 30、创新性 20。
7. 初始参考题为“围绕学生成绩信息存证与查询实现一个成绩管理应用”，允许原创扩展和自拟题。

## 2. CCF 第五届竞赛约束

依据 2026 年竞赛官网：

1. 每队最多 4 名学生并需要 1 名指导教师；不可跨校组队，每人只能参加一支队伍。
2. 作品围绕区块链技术创新或应用创新自主命题，平台不限，但本项目仍须满足课程的 Fabric 硬约束。
3. 作品需有创新性、实用性，并重点体现安全性或隐私性。
4. 函评提交设计报告、测试报告、可执行代码等；中文材料按规定命名和控制大小。
5. 函评匿名：所有提交材料不得出现学校、指导教师、队员姓名等身份信息，否则记 0 分。
6. 决赛预计为 15 分钟陈述、演示和测试，加 5 分钟提问。
7. 禁止抄袭、侵犯知识产权、发币、洗钱等不合规内容；比赛不接受论文作为参赛作品。

## 4. 当前验收原则

- 不是“数据库加一层哈希”，而是由多组织背书、可撤销/更正、可审计的完整业务闭环。
- 链上仅放必要的索引、承诺、状态和审计事实；成绩原文默认不公开上链。
- 隐私能力必须有可运行实现和攻击/边界测试，不能只写在设计报告里。
- 全程只维护一个项目、一套代码和一条产品主线；先达到课程验收里程碑，再在原项目上连续增加密码学与跨机构能力，不建立所谓“课程版/竞赛版”分叉。

## 5. 每阶段 UI 验收门槛

每个包含前端变化的阶段在关闭前必须完成以下工作，任何一项缺失都不能标记为阶段完成：

1. 使用真实浏览器逐页检查本阶段新增或受影响的界面，包括正常态、空状态、错误态、登录/权限态和关键操作结果。
2. 至少检查 1280×720 桌面视口和 390×844 移动视口；记录页面 `scrollWidth`，确认不存在意外横向溢出。
3. 检查标题、文字、表单标签、按钮、间距、对齐、折行、颜色对比、遮挡和导航可达性，不能只以 DOM 或接口测试代替视觉检查。
4. 检查浏览器 console 的 warning/error；发现问题应先修复，再重新截图。
5. 将验收截图存入 `reports/assets/iteration-N/`，文件名包含页面、状态和视口；截图不得包含密码、会话令牌、私有成绩明文或其他敏感信息。
6. 在对应阶段实验报告中直接嵌入截图，并在图注附近写明视口、页面状态和验收结论；不得只写截图文件路径或“验收通过”。
7. 提交前验证 Markdown 中的全部图片链接有效，并将截图随报告同步到本机、GitHub 和学校服务器。
