# 四角色工作台与产品信息架构 v0.1

日期：2026-08-25

## 1. 统一项目原则

ChainGrade 的课程答辩版本和 CCF 竞赛版本是同一个持续演进项目。四角色工作台不是另建的演示前端，而是现有链码、Gateway API、隐私模型的产品入口；后续成绩修订和申诉继续进入同一导航与领域模型。

## 2. 角色视图

| 角色 | 当前入口 | 当前数据范围 | 下一阶段增强 |
| --- | --- | --- | --- |
| 教师 / issuer | 创建成绩草稿 | 录入详情，接收公共凭证与交易证据 | 修订草稿、批量导入、会话身份 |
| 院系复核员 / reviewer | 查询并批准 | 仅查看公共承诺与审计字段 | 待办队列、驳回、修订/申诉裁决 |
| 学生 / student | 查看凭证 | 当前状态、版本、签发组织、时间 | 本人属性校验、详情读取、申诉、授权披露 |
| 公开验证者 / verifier | 哈希验真 | 真实性、有效性、版本与审计交易 | 二维码/短链接、选择性披露证明 |

角色分离由两层共同实现：页面减少误操作和不必要披露；API 动作到 Fabric 身份的固定映射及链码属性校验提供安全边界。不能把页面隐藏描述为访问控制。

## 3. 页面流

1. 教师提交合成成绩详情，前端调用 `POST /api/v1/credentials/drafts`。
2. API 规范化详情并通过 issuer Gateway 身份发送 transient data；页面只显示哈希承诺和交易 ID。
3. 复核员按凭证标识读取公共记录，使用 reviewer 身份调用批准接口。
4. 学生凭证夹读取凭证当前状态，暂不读取私有成绩明文。
5. 验证者输入凭证标识及持有者提供的详情哈希；正确哈希显示可信，错误哈希显示警告。

## 4. 前端实现选择

- 继续使用 Vue 3 Composition API，不为五个简单视图新增路由依赖。
- 使用 URL hash 保存当前视图，支持刷新、后退和直接链接。
- Vite 仅在开发环境把 `/api` 代理到 `127.0.0.1:3000`；生产部署由同源反向代理承载。
- 所有异步操作呈现加载、成功和失败状态，批准成功后按钮不可再次提交。
- 390 px 断点下表单改为单列，导航改为菜单，长哈希允许安全换行。

## 5. 隐私与可信表达

- 页面使用的学生、课程、盐值与成绩均为合成演示数据。
- 复核页面不展示成绩明文，只展示公共哈希和身份哈希。
- 页面明确说明“下一阶段”的申诉功能，避免把占位入口宣传为已实现。
- 首页声明连接真实 Fabric，同时保留“开发拓扑”边界；不把 test-network 描述为生产网络。

## 6. 下一阶段接口落点

修订和申诉不新增独立产品：教师端增加修订草稿，学生端增加申诉表单，复核端增加两类待办及处理结论，公开验真继续只读取当前有效版本与版本链证据。后端同时增加稳定业务错误码、终端会话到 Fabric 身份映射及学生本人授权检查。
