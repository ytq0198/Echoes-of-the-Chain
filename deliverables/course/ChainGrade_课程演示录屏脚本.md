# ChainGrade 演示视频录制与前端操作手册

## 1. 当前可用状态

本文档用于录制 ChainGrade 的课程或竞赛演示视频。课程提交本身不强制要求演示视频，但视频可作为答辩备份和竞赛展示材料。

2026 年 9 月 10 日已完成一次真实环境启动和检查：

| 项目 | 当前结果 |
|---|---|
| 账本模式 | Hyperledger Fabric 2.5.16 真实账本 |
| 网络 | 1 个 Orderer、Org1/Org2 各 1 个 Peer |
| 链码 | `grade` 0.9，CCaaS 端口 9999 |
| API | 服务器 `127.0.0.1:3000`，已健康 |
| Web | 服务器 `127.0.0.1:5173`，已健康 |
| 本机入口 | `http://127.0.0.1:5173/` |
| 固定演示凭证 | `cred:demo:blockchain-2026`，状态 `ACTIVE` |
| 固定演示申诉 | `appeal:demo:blockchain-2026`，状态 `OPEN` |

固定数据的重复播种结果显示 `credentialCreated=false`、`appealCreated=false`，说明本次启动复用了既有记录，没有为了预检重复写链。

## 2. 录制方式

推荐使用 OBS Studio；如果只需要快速录制，也可以使用 Windows 自带的 Xbox Game Bar，按 `Win + Alt + R` 开始或结束录制。

推荐参数：

- 画布与输出：1920 × 1080；
- 帧率：30 fps；
- 浏览器缩放：100%；
- 只录浏览器窗口，不录终端、任务栏通知和密码管理器弹窗；
- 麦克风先试录 15 秒，确认没有爆音、底噪过大或音画不同步；
- 登录、填写隐私盐和生成 bearer token 时暂停录制，或使用 OBS 遮罩挡住敏感区域。

录制前关闭微信、QQ、邮件和系统通知。不要在画面中展示服务器密码、`preview.env`、私钥、真实学生数据、一次性披露令牌或完整授权二维码。

## 3. 环境启动与访问

### 3.1 服务器端

服务器项目目录固定为：

```text
/mnt/localDisk3/weizian/Echoes-of-the-Chain
```

以后重新录制时，在服务器依次执行：

```bash
cd /mnt/localDisk3/weizian/Echoes-of-the-Chain
./infra/fabric-native/native-network.sh up
./infra/fabric-native/deploy-chaincode.sh start
PATH="$PWD/.tools/node/bin:$PATH" .tools/node/bin/corepack pnpm --filter @chaingrade/api seed:native
./infra/demo/preview.sh start
./infra/demo/preview.sh status
```

这些命令恢复既有账本，不执行重置。不要在录制前运行 `reset`、`restore`、`docker system prune` 或重新部署链码定义。

### 3.2 Windows 本机隧道

在 PowerShell 中保持下面的窗口运行：

```powershell
ssh -N -p 9961 -L 5173:127.0.0.1:5173 weizian@10.98.36.128
```

浏览器打开：

```text
http://127.0.0.1:5173/
```

页面左上方应显示“Fabric 真实账本已连接”。只需要转发 5173；前端会把 `/api` 请求同源转发到服务器 API 的 3000 端口。

## 4. 演示账号

| 工作台 | 用户名 | 是否登录 |
|---|---|---|
| 教师签发 | `demo-issuer` | 是 |
| 独立复核 | `demo-reviewer` | 是 |
| 学生凭证 | `demo-student` | 是 |
| 公开验真 | 无 | 否 |

密码保存在服务器 Git 忽略目录 `.runtime/private/preview.env` 中。录制前自行查看对应的 `AUTH_ISSUER_PASSWORD`、`AUTH_REVIEWER_PASSWORD` 和 `AUTH_STUDENT_PASSWORD`，不要把文件或密码录入画面。建议暂停录制完成登录，再恢复录制。

切换角色时，点击页面右上方“退出”，再进入下一个工作台登录。直接用另一角色打开不匹配的工作台，会看到“当前角色与工作台不匹配”，不适合作为正式演示画面。

## 5. 推荐录制方案：完整可信生命周期

建议成片 7–9 分钟。为了让各阶段在一次录制中能连续查询，先在纸上写下三个唯一标识。每次重录必须更换后缀，因为区块链业务键不可重复。

例如本次可使用：

```text
原凭证：cred:recording:20260910-01
申诉：appeal:recording:20260910-01
修订凭证：cred:recording:20260910-01-v2
披露授权：grant:recording:20260910-01
```

如果已经提交过上述 ID，将末尾 `01` 改成 `02`，不要尝试覆盖旧记录。

### 步骤 1：首页说明项目与真实网络（约 30 秒）

1. 打开首页“可信成绩工作台”。
2. 将鼠标依次指向“Fabric 真实账本已连接”“Fabric 2.5 LTS”“chaingrade”“grade 0.9”和“Org1 / Org2”。
3. 简要说明：项目不是只保存一条成绩，而是连接签发、独立复核、学生持有、申诉修订和外部验真。
4. 不要在首页停留过久，30 秒内进入教师工作台。

应观察到：页面显示真实 Fabric 连接，固定流程状态为 `ACTIVE`，私有成绩位于隐式私有集合。

### 步骤 2：教师创建待复核凭证（约 60 秒）

1. 点击顶部“教师签发”。
2. 暂停录制，使用 `demo-issuer` 登录；登录后恢复录制。
3. 在“创建待复核成绩草稿”中填写：
   - 凭证标识：本次唯一的原凭证 ID；
   - 课程名称：可使用“区块链技术与应用”；
   - 成绩与等级：使用合成数据，例如 92、A；
   - Schema 版本：1.0；
   - 学生匿名标识与课程标识：保留页面已填入的 64 位 SHA-256；
   - 隐私盐值：使用不少于 16 位的新演示盐值。
4. 点击“提交至 Fabric”。
5. 等待结果卡片出现，展示状态 `PENDING_REVIEW`、详情承诺和交易 ID。

口播重点：课程名、分数、等级和盐值经 transient data 进入私有集合；公共账本只保存哈希承诺、状态和审计字段。

注意：隐私盐值不应完整出现在公开视频中。可先暂停录制填入，恢复后直接提交。

### 步骤 3：复核员独立批准（约 45 秒）

1. 点击“退出”。
2. 点击“独立复核”，暂停录制并使用 `demo-reviewer` 登录。
3. 在“链上凭证复核队列”保持“待复核”筛选，找到刚创建的凭证，点击“打开复核”。
4. 如果列表中暂未出现，也可在“凭证标识”输入框粘贴 ID，点击“查询账本”。
5. 展示签发组织、学生匿名标识、课程标识和详情哈希；指出复核员看不到成绩明文。
6. 点击“批准并激活”。

应观察到：凭证由 `PENDING_REVIEW` 变为 `ACTIVE`。

口播重点：issuer 与 reviewer 使用不同属性证书，系统不允许签发者自行完成复核。

### 步骤 4：学生查看本人凭证与私有成绩（约 50 秒）

1. 点击“退出”。
2. 点击“学生凭证”，暂停录制并使用 `demo-student` 登录。
3. 在“由学生证书解锁的凭证”中找到新凭证，点击“打开凭证”；或输入凭证 ID 后点击“打开凭证”。
4. 展示 `ACTIVE` 状态、签发组织和版本号。
5. 点击“授权读取成绩”。
6. 展示“仅向本人披露的成绩详情”，说明响应使用 `Cache-Control: no-store`，盐值不会明文展示。

口播重点：学生访问不是靠知道凭证 ID，而是链码比较证书中的 `subject.hash` 与凭证主体哈希。

### 步骤 5：学生提交申诉（约 45 秒）

1. 点击“发起成绩申诉”，页面滚动到“提交轻量成绩申诉”。
2. 填写本次唯一申诉 ID。
3. 使用合成理由，例如“实验成绩未计入总评，请复核原始评分记录”。
4. 暂停录制填写不少于 16 位的新申诉盐值。
5. 点击“由学生证书提交申诉”。

应观察到：申诉状态为 `OPEN`，公共页面只显示理由哈希，不显示理由明文。

### 步骤 6：复核员接受申诉（约 40 秒）

1. 退出学生账号并重新使用 `demo-reviewer` 登录“独立复核”。
2. 向下找到“申诉复核与结论承诺”。
3. 保持状态“待处理”，选择刚提交的申诉并点击“处理”；也可输入申诉 ID 后点击“按标识查询”。
4. 选择“接受申诉”，填写简短结论和新的隐私盐值，再提交处理。

应观察到：申诉变为 `RESOLVED_ACCEPTED`。

必须口播：接受申诉不会直接修改成绩，只允许进入后续修订流程；复核员不能绕过教师签发步骤直接改分。

### 步骤 7：教师创建修订版本（约 50 秒）

1. 退出 reviewer，重新以 `demo-issuer` 进入“教师签发”。
2. 向下找到“创建不可覆盖的修订版本”。
3. 原凭证标识填写本次原凭证 ID；新版本标识填写带 `-v2` 的修订凭证 ID。
4. 填写修订后的合成成绩、等级、课程名称和新盐值。
5. 点击“创建修订草稿”。

应观察到：新版本先进入 `PENDING_REVIEW`；原凭证此时仍保持 `ACTIVE`，不会提前失效。

### 步骤 8：复核员批准修订（约 45 秒）

1. 退出 issuer，重新以 `demo-reviewer` 登录。
2. 查询新版本 ID，点击“批准并激活”。
3. 在状态筛选中分别查看：
   - 新版本：`ACTIVE`；
   - 原版本：`SUPERSEDED`。

口播重点：旧对象没有被覆盖；新版本通过 `previousCredentialId` 链接旧版本，只有独立复核通过时才完成原子状态替换。

### 步骤 9：学生导出标准 VC（约 50 秒）

1. 退出 reviewer，以 `demo-student` 登录“学生凭证”。
2. 打开新版本凭证。
3. 点击“导出标准凭证”。
4. 在“导出字段”中选择需要的字段，建议保留课程名称、成绩分数和成绩等级。
5. 点击“生成标准凭证”。
6. 生成后点击“下载凭证 JSON”，记住下载位置。

口播重点：文件由 Ed25519 签名，但签名正确只是必要条件，最终仍需检查链上状态和详情锚定。

### 步骤 10：公开页面完成文件验真（约 50 秒）

1. 点击“退出”，再打开“公开验真”；公开验真无需登录。
2. 先在“凭证标识”中输入新版本 ID，详情哈希留空，点击“开始验真”。
3. 展示“凭证真实且当前有效”、签发组织、版本和审计交易；说明公开查询不返回成绩明文。
4. 在“上传凭证文件验真”区域选择刚才下载的 JSON。
5. 展示三段结果：
   - 签名校验：Ed25519 签名有效；
   - 链上状态：`ACTIVE`；
   - 详情锚定：详情哈希和学生标识一致。

不要只说“验签成功”，应明确文件可信由结构、签发者信任、签名、状态/有效期和链上锚定共同决定。

### 步骤 11：可选——演示限时最小披露（约 60 秒）

此步骤适合竞赛视频；课程视频时间紧时可以省略。

1. 以学生身份打开新版本凭证，点击“创建披露授权”。
2. 使用唯一 grant ID，只勾选最少必要字段，例如课程名称和等级，不勾选成绩分数。
3. 填写授权用途、指定验证者、有效期和最大使用次数 1。
4. 点击“生成限时授权”。
5. bearer token 和二维码只显示一次。公开视频中必须遮住完整链接、token 和二维码。
6. 点击“预览最小披露”，进入公开验真页后点击“读取授权字段”。
7. 展示返回结果只包含被授权字段，使用次数由 0/1 变为 1/1。

口播边界：当前实现是 bearer capability 与字段级授权，不是 BBS+ 选择性披露或零知识证明。

## 6. 快速补录方案：不新增链上数据

如果完整录制中只有口播或画面需要补录，不要再次创建成绩。使用固定凭证完成只读镜头：

1. 首页展示“Fabric 真实账本已连接”。
2. 打开“公开验真”。
3. 凭证标识输入 `cred:demo:blockchain-2026`。
4. 详情哈希留空，点击“开始验真”。
5. 展示签发组织、`ACTIVE`、版本和审计交易。
6. 如需学生镜头，以 `demo-student` 登录并从本人凭证列表打开固定演示凭证。

该方案适合补拍开场、公开验真、学生持有和隐私说明，不会改变账本状态。

## 7. 建议剪辑结构

| 时间 | 画面 | 必须说清楚的结论 |
|---|---|---|
| 0:00–0:30 | 首页与真实网络状态 | 同一项目覆盖可信成绩生命周期 |
| 0:30–1:30 | 教师签发 | 明文进入私有集合，公共账本保存承诺 |
| 1:30–2:15 | 独立复核 | 签发与复核职责分离 |
| 2:15–3:10 | 学生持有与私有读取 | `subject.hash` 绑定本人访问 |
| 3:10–4:40 | 申诉、接受与修订 | 接受申诉不直接改分，修订不覆盖历史 |
| 4:40–5:40 | 标准 VC 导出与文件验真 | 签名、状态和锚定共同成立 |
| 5:40–6:30 | 有限披露或性能证据 | 只披露授权字段，或展示实测结果 |
| 6:30–7:00 | 回到首页或 PPT 总结页 | 谁签发、谁复核、谁能看、如何纠错、如何验证、故障后是否一致 |

角色切换和密码输入可剪掉；每次关键提交后保留 2–3 秒静止画面，让观众看清状态和交易 ID。

## 8. 常见问题与回退

| 现象 | 处理方法 |
|---|---|
| 页面打不开 | 确认 PowerShell 的 SSH 隧道仍在运行，并访问 `http://127.0.0.1:5173/` |
| 页面显示账本不可用 | 在服务器执行 `./infra/demo/preview.sh status`，再检查 native network 和 chaincode 状态 |
| 登录后提示角色不匹配 | 点击“退出”，进入正确工作台后使用对应账号登录 |
| 新凭证返回冲突 | 业务 ID 已存在；只修改本次录制后缀，不要覆盖或重置账本 |
| reviewer 队列没有记录 | 检查筛选是否为“待复核”，或直接按凭证 ID 查询 |
| student 看不到新记录 | 确认凭证使用页面默认学生匿名哈希，且已经由 reviewer 激活 |
| 无法发起申诉 | 只有 `ACTIVE` 凭证允许申诉，且学生证书必须与主体哈希一致 |
| VC 文件验证失败 | 确认上传的是最后一次生成的 JSON，新版本仍为 `ACTIVE`，文件没有被编辑 |
| 生成披露后链接丢失 | token 只显示一次；重新使用新的 grant ID 创建，不能恢复旧 token |
| 校园网突然中断 | 使用已录好的视频和 PPT 证据页继续答辩，不切换为未标注的模拟账本 |

## 9. 录制完成后的检查

从头到尾完整观看一次，并逐项确认：

- 画面左上显示的是真实 Fabric 连接；
- 没有出现密码、隐私盐、私钥、完整 bearer token、个人通知或真实学生数据；
- 原版本最终为 `SUPERSEDED`，新版本最终为 `ACTIVE`；
- 口播明确“申诉接受不会直接修改成绩”；
- VC 没有被表述为只验签名；
- 单 Orderer 只表述为“可恢复但非高可用”；
- 视频中的性能数字与最终实验报告一致；
- 音量稳定，鼠标没有快速晃动，关键状态至少停留 2 秒；
- 视频保存在本地提交目录，不提交到 Git 仓库。

## 10. 录制结束后停止服务

本机先关闭运行 SSH 隧道的 PowerShell 窗口，或按 `Ctrl + C`。

服务器只停止临时前后端：

```bash
cd /mnt/localDisk3/weizian/Echoes-of-the-Chain
./infra/demo/preview.sh stop
```

这不会停止 Fabric。若确认近期不再录制，再完整关闭：

```bash
./infra/fabric-native/deploy-chaincode.sh stop
./infra/fabric-native/native-network.sh down
```

不要删除 `.runtime/native-fabric`，其中包含需要复用的账本状态。
