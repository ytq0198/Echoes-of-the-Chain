# ChainGrade 课程答辩脚本（7 分钟）

## 0:00–0:45 问题与价值

传统成绩系统能修改最终结果，却难以向学生和第三方解释“谁在何时基于什么理由完成了签发、复核、修订和撤销”。ChainGrade 用 Hyperledger Fabric 保存状态与承诺，用私有数据集合保护成绩明文，让可信审计与隐私最小化同时成立。

## 0:45–1:35 方案与架构

用一张架构图讲清浏览器、Fastify Gateway、Fabric 双组织、链码状态机和隐式私有集合。强调公共账本保存匿名标识、详情哈希、版本和状态；成绩、盐值、申诉正文与决定理由明文不上公共账本。

## 1:35–4:55 现场主线

1. 首页（20 秒）：指出真实 Fabric 连接状态和四角色入口。
2. 教师端（50 秒）：展示 CSV 预览与原子批量提交，说明一条冲突会使整批不落账。
3. 复核端（45 秒）：打开待复核记录并批准，强调签发与复核职责分离。
4. 学生端（65 秒）：查看本人私有成绩、提交轻量申诉，说明链上只保存申诉承诺。
5. 修订闭环（40 秒）：展示原凭证到新版本的关联及复核状态。
6. 公开验真/二维码（35 秒）：用正确详情哈希得到有效结论，再说明错误哈希不会泄露成绩。
7. 有限披露（30 秒）：学生选择字段、用途、验证者、有效期和次数；明确这是受控 bearer capability，不宣称零知识证明。

优先复用已播种凭证 `cred:demo:blockchain-2026` 和申诉 `appeal:demo:blockchain-2026`，不要在有限时间内依赖多次手工输入。批量写入作为一次独立的现场新增交易。

## 4:55–6:10 工程可信性与创新

展示双 Peer 同高度/同哈希、链码版本、52 项自动测试、冷备份校验和恢复演练。创新点按“隐私数据边界、可审计版本/申诉、原子批量、有限披露”四项陈述，不用代币、NFT 或空泛上链包装成绩管理。

## 6:10–7:00 结果、边界与未来

总结已经完成的真实 Fabric 闭环、桌面/移动端 UI 和故障降级。主动声明尚未完成 BBS+ 不可链接匿名凭证、跨校互认和正式统一身份接入；这些是同一项目的竞赛深化方向，不是另一个系统。

## 预设问答

- 为什么不用普通数据库？数据库仍适合查询和业务缓存；Fabric 用于跨职责主体共同确认、不可抵赖的状态与版本证据，不把所有数据都放链上。
- 成绩哈希会不会被穷举？公共账本不放裸成绩哈希，而是对含随机盐的规范化详情做承诺；盐和明文留在私有集合。
- 单 orderer 是否高可用？当前是课程/演示拓扑，不能宣称生产高可用；竞赛部署计划扩展多 orderer 并做故障实验。
- 有限披露是否等于零知识证明？不是。当前是有用途、期限、次数约束的受控访问能力，BBS+/匿名凭证仍是后续技术尖峰。
