# 01_成绩可信不等于把成绩写上链

各位老师好，我们的项目是 ChainGrade。我们一开始就不把目标定义为“把成绩写到链上”，因为写入一次并不等于整个过程可信。我们真正要解决的是：身份有边界、复核有过程、隐私仍可验证。接下来我会先说明为什么简单上链不够，再讲我们的设计和真实运行证据。

---

# 02_简单上链仍然留下三道硬伤

不可篡改只能回答“写入之后有没有被悄悄改过”，却不能自动证明写入者正确。成绩系统还同时面对三道硬伤：签发者可能越权或误写；成绩明文永久公开会伤害隐私；现实错误又必须允许纠正。如果直接覆盖旧值，历史证据就消失；如果完全不允许修订，系统又不符合教务现实。因此问题的核心不是数据存在哪里，而是变化如何被治理。

---

# 03_公开承诺私有详情受控状态

我们的总设计分成三层。公共账本只保存匿名标识、SHA-256 承诺、状态和审计字段，所以任何人可以验证记录是否一致，却看不到成绩明文。课程、分数、等级、申诉理由和复核决定进入隐式私有集合。所有变化再通过状态机约束，于是系统同时做到公开可验、明文不公开、允许纠错而不覆盖历史。

---

# 04_一条交易穿过四层责任边界

一条真实交易从四角色工作台开始，经 Vue 页面进入 Node API，再由 Fabric Gateway 提交给双组织网络。浏览器只持有受签名的 HttpOnly 会话和 CSRF 令牌，不能提交证书路径，更不能选择任意 MSP 身份；API 会把动作映射到服务器固定身份。成绩、申诉和决定正文走 transient 私有路径，链码在背书节点内复算哈希。这样，前端体验、应用权限和账本规则不是三套约定，而是一条连续的责任边界。

---

# 05_四类角色各自只做该做的事

我们没有设置可以绕过流程的超级管理员。签发者能创建和批量导入凭证，也能提出修订，但不能自行批准；复核者独立做批准、拒绝、撤销和申诉决定。学生只能查看本人私有详情、发起申诉或授权披露，外部验证者则只能查询公开状态或消费被授权的字段。会话、API 和链码三层重复检查角色，目的是让任何单一主体都不能独立制造一条“看起来可信”的成绩。

---

# 06_凭证不会被覆盖只会留下下一段历史

这里展示的是凭证状态机。凭证创建后进入待复核，只有复核者批准才会成为 ACTIVE；拒绝和撤销都保留原记录。修订不是数据库 UPDATE，而是创建一个新凭证并链接旧版本，旧凭证转为已替代，所以审计者仍能验证前一段历史。学生申诉同样进入受控分支，而不是在系统外通过口头或表格处理。

---

# 07_轻量申诉让纠错进入同一条证据链

申诉流程刻意保持轻量，但没有绕开隐私和审计规则。学生通过 transient 提交理由，链码复算 reasonHash；复核员再提交私有决定正文，并在公共账本留下 resolutionHash、身份和时间。右侧是真实浏览器验收中的学生申诉进度，不是设计原型。这样，纠错能够发生，但双方的原始陈述不会被公开，也不会被事后替换。

---

# 08_同一份成绩对不同人暴露不同内容

同一份凭证在三种视角下暴露不同内容。公众只能看到 detailHash、匿名学生和课程哈希、状态与交易审计；学生本人通过身份校验后，能读取课程、分数和等级。外部验证者还需要学生授权，且授权同时绑定字段白名单、用途、验证者、过期时间和一到十次使用上限。随机令牌本身不写链，链上只保存 tokenHash，因此公开查询和定向披露不会合并成一次过度公开。

---

# 09_产品不是四张原型而是四个真实工作台

前面的机制已经落实到角色工作台。左侧签发端负责创建和查看账本队列，右侧复核端处理独立待审任务；两张图都是 Fabric 模式下的真实浏览器验收。界面中的状态来自 Gateway 返回值，而不是前端模拟。角色如果越权，会在会话、API 和链码三层被拒绝，所以好看的界面没有取代底层约束。

---

# 10_隐私边界也能在界面上被看见

这两张图展示同一条隐私边界在产品中的可见结果。学生本人登录后可以看到自己的课程、分数和等级；公开验真端无需登录，但只显示 ACTIVE 状态、哈希承诺和交易信息，没有成绩明文。这种差异不是报告里的安全承诺，而是浏览器到链码完整执行后的真实行为。也正因为如此，验证者能够确认凭证有效，而不需要获得整份成绩。

---

# 11_真实Fabric的证据不是一行连接成功

我们没有把“接口返回连接成功”当作区块链证据。签发者创建、复核者独立批准后，凭证进入 ACTIVE，并产生交易 ID c7f5827e 开头、becf7a7 结尾的真实交易。恢复彩排中两个 Peer 的账本高度都是十二，当前区块哈希和前序区块哈希完全一致。批量导入也遵守原子语义，只要一行校验失败，整批就是零写入。

---

# 12_把完成拆成四组可复核指标

最后看工程指标。项目实现二十五个链码方法和二十八个 HTTP 路由，一百二十项项目测试全部通过，其中 shared 三十三项、chaincode 二十项、API 六十七项，另有七项基准工具测试通过。隔离性能矩阵包含七类负载、四档并发、每档三次，共八十四个正式单元，合法请求失败率为零；并发二十时公开验证吞吐中位数为每秒七百四十六点六一四次，P95 为三十八点二零二毫秒。我们也保留局限：单 orderer 不具备写入高可用，这些数字只描述单机共享宿主上的课程实验条件。

---

# 13_可信来自可验证流程而不是上链口号

回到开头，ChainGrade 的价值不是把一个数字写进区块，而是把身份、复核、隐私、修订与申诉放进同一条可验证流程。我们已经完成真实 Fabric 双组织闭环、四角色产品、标准 VC 文件互操作和可重复可靠性基准，并用一百二十项项目测试、双 Peer 一致性、真实交易、篡改失败和故障恢复时间验证它。下一步的 BBS+、三 orderer 和真实教务接入仍是明确边界，而不是已经完成的功能。谢谢各位老师，欢迎从为什么用链、如何保护隐私和证据是否真实三个角度提问。
