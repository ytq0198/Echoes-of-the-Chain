# Iteration 20 阶段实验：课程大作业最终收口

## 1. 阶段目的

两名组员的 PR 已合并后，项目功能事实发生了两项重要变化：标准 VC 文件互操作已经落地，可重复性能与故障恢复基准也已经完成。如果只保留旧报告，会造成“代码完成、材料仍说未完成”的矛盾。本阶段因此不扩展产品，而是统一代码、证据和答辩材料。

## 2. 成员成果归属

贡献评分按组长指定的 10 分制固定为魏子安 4 分、强璞 3 分、阳震 3 分。强璞负责的 VC 工作对应 PR #2；阳震负责的性能与可靠性工作对应 PR #1；魏子安负责前序总体设计与基础实现，并完成两项 PR 的审核、修正、集成和最终材料收口。合并提交作者不能覆盖原始 PR 的工作归属。

## 3. 材料更新结果

- 最终实验报告补入 VC 签发/导出/上传验真、负向测试、84 个正式负载单元、吞吐延迟和故障恢复数据。
- 项目介绍更新为 16 页，功能表由六类改为七类，并明确后续只保留 BBS+/零知识阈值证明、三 orderer 高可用和真实教务接入。
- 13 页答辩 PPT 的证据页更新为 120 项项目测试、7 项基准工具测试、28 条 HTTP 路由及实测性能；结论页不再把 VC 和基准写成计划。
- 新增最终提交清单与演示录屏脚本，明确唯一提交入口和最后的人工动作。

## 4. 文档视觉验收

| 成品 | 验收方式 | 结果 |
| --- | --- | --- |

| 项目介绍 DOCX | Microsoft Word 导出 PDF，Poppler 渲染 16 页；首轮发现并修正功能数与结论旧措辞 | 16/16 页通过；修订页 7、16 再次检查无溢出 |

## 5. 最终边界

课程所需源代码、实验报告、项目介绍、答辩 PPT 与贡献评分已经形成。演示讲解视频需要三名学生本人录制与确认，仓库只提供脚本和运行手册；组号未知，因此最终压缩包名称也只能在提交前填写。该边界是人为身份与提交信息要求，不是工程缺陷。

## 6. 防跑偏检查

- 所有材料仍描述同一个 ChainGrade 仓库、同一 Fabric 网络、同一 API 和 Web，不存在课程版与竞赛版两个产品。
- 性能数据只说明本次受控实验结果，不外推为生产 SLA。
- 当前为单 orderer，故障恢复数据不能被描述成多 orderer 高可用。
- BBS+/零知识阈值证明和真实教务接入仍是后续方向，不写成已实现能力。
