## 3. 失败与处理

第一次恢复时，Orderer 重放 WAL 和完成单节点 Raft 选主所需时间超过启动脚本等待窗口，脚本报告 7053 尚未开放。日志随后显示 Orderer 已在既有高度恢复并成为 leader；再次执行幂等 `native-network.sh up` 后，两个 Peer 正常启动，没有重置数据。

链码启动后的首次播种还暴露了非交互 SSH 环境找不到 `node` 的问题。处理方式是显式把项目固定 Node 目录加入该条命令的 `PATH`，随后播种、生产构建和前后端启动全部成功。此问题没有修改项目或账本数据。

## 4. 文档核对

录屏手册中的按钮名称依据当前 Web 界面核对，包括“提交至 Fabric”“批准并激活”“授权读取成绩”“由学生证书提交申诉”“提交复核结论”“创建修订草稿”“生成标准凭证”“开始验真”和“读取授权字段”。

状态与报告保持一致：成绩使用 `PENDING_REVIEW / ACTIVE / REJECTED / REVOKED / SUPERSEDED`；申诉接受后为 `RESOLVED_ACCEPTED`，且不会直接修改成绩。标准 VC 的讲解明确包含签名、链上状态和详情锚定；有限披露明确标注为字段级 bearer capability，不称为 BBS+ 或零知识证明。

## 5. 当前边界

- 完整演示会写入新的合成凭证、申诉、修订和授权记录，因此每次正式重录必须使用新的业务 ID。
- 密码、隐私盐、私钥、完整 bearer token 和授权二维码不应进入公开视频。
- 当前单 Orderer 可以恢复，但不构成生产级高可用。
- 服务器和本机隧道已保持运行，录制结束后应按手册仅停止临时前后端；只有确定近期不再录制时才关闭 Fabric。
