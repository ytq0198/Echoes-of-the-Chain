# Iteration 14 启动记录：竞赛深化与组员平分

日期：2026-08-28

## 1. 决策

此前 ChainGrade 的架构、链码、API、Web、真实 Fabric 恢复、测试、课程报告和答辩材料均由组长魏子安完成。下一大阶段将日常实现平均交给强璞和阳震，组长只保留接口裁决、里程碑验收和最终合并职责。

根据当前缺口与 2026 年竞赛章程，阶段选择两项可量化且能并行完成的优化：

- 强璞：标准凭证互操作与验证体验，40 工作点；
- 阳震：可重复性能基准与故障证据，40 工作点。

## 2. 选择原因

现有项目已经有完整成绩闭环和隐私边界，继续增加普通后台功能对竞赛评分帮助较小。标准凭证层能证明项目不仅在自有页面中工作，还能导出和独立验证；性能与故障基准能补上当前报告明确承认的数据缺口。

完整 BBS+、学校 OIDC/SAML 和三 orderer 都需要更高外部依赖或更大拓扑改动，因此只列为伸展项。这样可以避免两名成员各自开一个无法收尾的研究分支。

## 3. 平衡方式

两人的工作包都包括约 44–50 小时投入，并同时包含设计、实现、自动测试、真实运行、失败分析和报告。强璞不是只负责“美化页面”，阳震也不是只负责“跑一个脚本”。两条轨道都必须形成可复核技术成果和本人 Git 记录。

## 4. 并行条件

- 两个分支从 `610a234` 开始；
- 强璞独占 VC shared/API/Web 路径，阳震独占 benchmark/infra/data 路径；
- 根脚本、共同证据索引和竞赛最终 PDF 由组长合并时更新；
- 阳震第一轮基准不依赖未合并的 VC API；
- 所有服务器实验限制在 `/mnt/localDisk3/weizian`，不得修改共享 Docker 或其他用户目录。
- 两名成员使用本人 Git 姓名和邮箱提交，组长合并时保留原作者记录，不代写或重新归属提交。

## 5. 阶段退出条件

只有两条工作包各自达到 Definition of Done 才算完成。若其中一条只完成研究说明、没有自动测试和真实证据，不按一半阶段成果计算。浏览器验收截图必须嵌入强璞报告；性能原始数据、聚合方法和故障记录必须进入阳震报告。
