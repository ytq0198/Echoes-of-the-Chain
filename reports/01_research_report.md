# 第一阶段实验报告：立项与技术调研

日期：2026-08-25

## 实验目标

在不脱离课程 Hyperledger Fabric 成绩管理参考题的前提下，筛选一个适合三人团队完成、能够继续参加 CCF 竞赛的产品方向。

## 调研方法

1. 对两份课程 PDF 进行文本提取和逐页渲染核对。
2. 访问 CCF 官网核验 2026 年第五届比赛的参赛、作品和匿名要求。
3. 查阅 W3C VC 2.0、Fabric 私有数据等一手标准与官方文档。
4. 查阅教育区块链、成绩交换、选择性披露相关论文。
5. 通过 GitHub 页面与公开 API 比较相关开源项目的功能、活跃度和许可。
6. 通过 SSH 对指定服务器目录与基础软件做只读检查。

## 关键观察

- 课程评分的 60% 来自实用度和完整性，因此应先形成完整业务闭环，再叠加高级密码学。
- CCF 竞赛明确强调安全或隐私；把成绩明文放到所有 Fabric peer 上不符合这一导向。
- Fabric 的私有数据集合解决组织间可见性，但不自动解决学生向外部验证方最小披露和多次验证关联问题。
- W3C VC 的 issuer-holder-verifier 模型与“学校-学生-用人单位/其他学校”天然对应。
- 高质量实现应同时处理签发、版本、撤销、更正、授权、验证和审计，而不是只实现新增/查询两个接口。
- BBS+/AnonCreds 具有竞赛亮点，但集成风险高，需要以独立技术尖峰验证，不能成为 MVP 的单点阻塞。

## 实验结论

方向 A“隐私保护型可信学业凭证”综合得分最高。建议采用 A 为主、吸收 C 的成绩修订/申诉流程，并在同一项目后续迭代中加入跨校学分互认。详细比较见 `design/01_research_and_direction_options.md`。

## 风险与后续验证

1. 对 Fabric 2.5 + Gateway SDK + TypeScript 链码建立最小端到端交易样例。
2. 对加盐 Merkle 披露、BBS+ 和匿名凭证分别建立威胁/性能对比，不自研密码学原语。
3. 验证多组织背书、私有数据不可见性、撤销状态和一次性授权并发消费。
4. 使用合成学生数据，绝不使用真实成绩或学号。
5. 同一项目可按课程与竞赛的提交格式生成不同材料，其中竞赛材料必须自动匿名；材料模板差异不代表代码或产品分叉。
